These notes summarize the Module 1 notebooks: foundational models, prompting, tools, web search, memory, multimodal messages, and the personal-chef example.

## 1. The big picture

An AI application can be thought of as a flow:

1. A **model** receives input and generates output.
2. A **prompt** gives the model instructions and context.
3. An **agent** can decide to call tools, such as a calculator or web search.
4. **Memory** can preserve conversation history between calls.
5. **Multimodal messages** can contain text, images, or audio.
6. A complete application combines these parts for a specific task.

Use the simplest setup that meets the task. A plain model call is enough for a direct question. Use an agent when it needs tools or other orchestration.

## 2. Environment variables and API keys

Several notebooks begin with:

```python
from dotenv import load_dotenv

load_dotenv()
```

`load_dotenv()` reads a local `.env` file and places its settings into the Python process environment. Provider clients commonly read API keys from environment variables.

Example `.env` entry:

```text
OPENAI_API_KEY=your-key-here
```

Keep the real key private. Do not print it, commit the `.env` file, or paste it into a notebook shared with others. Other services (for example Tavily or Google) may need their own keys.

## 3. Foundational models: initialize and invoke

### Subject

A language model takes input—usually text—and returns a generated response. LangChain provides a common interface so you can initialize models and call them similarly across supported providers.

### Why use it?

Use a model directly when the task is a straightforward exchange and does not need tools, persistent state, or an agent workflow.

### Basic syntax

```python
from langchain.chat_models import init_chat_model

model = init_chat_model(
    model="gpt-5-nano",
    use_responses_api=True,
)

response = model.invoke("What's the capital of the Moon?")
print(response.content)
```

- `init_chat_model(...)` configures the model integration.
- `model` selects the model/provider model name used by the notebook.
- `invoke(...)` sends one input and waits for the response.
- `response.content` is the assistant's user-facing answer. Other response fields may contain metadata or non-user-facing data.

The notebook also prints `response.response_metadata` to inspect information such as model and response identifiers. Metadata is useful for debugging; it is not the answer itself.

### Model settings and providers

Settings let you adjust how the model responds. The notebook demonstrates `temperature`:

```python
model = init_chat_model(
    model="gpt-5-nano",
    use_responses_api=True,
    temperature=1.0,
)
```

Temperature controls output variability, within the behavior supported by the model/provider. Lower values are generally more consistent; higher values can be more varied. It does not make an answer more factually correct.

The notebooks also show provider-specific examples (Anthropic and Google). A different provider may need an additional integration package, provider credentials, and provider-specific model options. Use model names and settings supported by your installed integration.

## 4. Agents and messages

### Subject

An agent is an application flow built around a model. Depending on its configuration, it can follow instructions, call tools, and manage message state.

### Why use it?

Use an agent when the model needs to choose and coordinate actions, such as searching the web before answering. For a simple prompt with no tools or workflow, a direct model call is often simpler.

### Basic agent syntax

```python
from langchain.agents import create_agent
from langchain.messages import HumanMessage

agent = create_agent(model="gpt-5-nano")

response = agent.invoke({
    "messages": [
        HumanMessage(content="What's the capital of the Moon?")
    ]
})

print(response["messages"][-1].content)
```

- `HumanMessage` labels content as a user message.
- `AIMessage` labels content as a previous assistant message.
- The list in `messages` is the conversation supplied to the agent.
- `response["messages"]` contains the resulting conversation messages; the final assistant reply is commonly the last item.
- `pprint(response)` is useful when exploring the whole returned object.

An `AIMessage` that you put in the input is history you supplied; it is not generated by that invocation. Do not present invented assistant history as fact unless that is intentional.

## 5. Prompting

### Subject

A prompt is the instruction and context sent to a model. Prompting examples in the notebook include basic prompts, system prompts, few-shot examples, and structured response instructions.

### Why use it?

Clear instructions make the desired task, style, boundaries, and output easier for the model to understand. Prompts guide a response but do not guarantee correctness.

### System prompt

A system prompt gives the agent its general role or behavior:

```python
system_prompt = (
    "You are a helpful assistant. Answer clearly and say when you are unsure."
)

agent = create_agent(
    model="gpt-5-nano",
    system_prompt=system_prompt,
)
```

Match the system prompt to the real task. For example, an instruction to invent science-fiction cities is a poor fit if the user wants an accurate description of a beer glass in an image.

### Few-shot prompting

Few-shot prompting provides examples of the input/output pattern you want:

```python
system_prompt = """
You invent fictional space-capital names.

User: What is the capital of Mars?
Assistant: Marsialis

User: What is the capital of Venus?
Assistant: Venusovia
"""
```

Examples demonstrate a pattern; they are not proof that the example claims are true.

### Requesting a structure in text

You can ask for a fixed layout:

```python
system_prompt = """
Suggest a fictional city using this format:
Name: ...
Location: ...
Vibe: ...
Economy: ...
"""
```

This is a natural-language request for formatting. If code needs reliable fields and types, use structured output instead.

## 6. Structured output with Pydantic

### Subject

Structured output asks the model to return data matching a schema, rather than only free-form prose.

### Why use it?

Use it when your program needs predictable named fields it can access, validate, or pass to another function.

### Syntax from the notebook

```python
from pydantic import BaseModel
from langchain.agents import create_agent

class CapitalInfo(BaseModel):
    name: str
    location: str
    vibe: str
    economy: str

agent = create_agent(
    model="gpt-5-nano",
    system_prompt="Invent a fictional capital city when asked.",
    response_format=CapitalInfo,
)

response = agent.invoke({
    "messages": [HumanMessage(content="Invent a capital for the Moon.")]
})

capital = response["structured_response"]
print(capital.name)
print(f"{capital.name} is located at {capital.location}")
```

`BaseModel` defines the expected fields and their types. The structured result is available under `response["structured_response"]`; access fields with dot notation, such as `.name`.

The schema constrains the response shape, not whether the content is factually true. A schema for an intentionally fictional city is appropriate for a creative task; it does not make a fictional answer real.

## 7. Tools

### Subject

A tool is a function an agent can call to perform a defined operation. The model typically decides when a tool is relevant, while the tool's Python function performs the actual operation.

### Why use it?

Models cannot reliably perform every task through text generation alone. Tools can provide precise calculations, access external data, or invoke application-specific functions.

### Define a tool

```python
from langchain.tools import tool

@tool
def square_root(x: float) -> float:
    """Calculate the square root of a non-negative number."""
    return x ** 0.5
```

The `@tool` decorator exposes the function as a LangChain tool. The function name, type annotations, and docstring help describe its purpose and input to the agent.

You can call a tool directly to test it:

```python
square_root.invoke({"x": 467})
```

Or supply it to an agent:

```python
agent = create_agent(
    model="gpt-5-nano",
    tools=[square_root],
    system_prompt="Use the square-root tool when a square root is needed.",
)

response = agent.invoke({
    "messages": [HumanMessage(content="What is the square root of 467?")]
})

print(response["messages"][-1].content)
```

Inspect `response["messages"]` or the assistant message's `tool_calls` to learn whether the agent called the tool and what it requested. Tool availability does not guarantee every answer will use a tool; instructions and model decisions matter.

For production tools, validate inputs and handle errors explicitly. Tool calls can have real-world side effects, so restrict them to operations the application is authorized to perform.

## 8. Web search with Tavily

### Subject

Web search is an external tool that can retrieve current information. It can help with questions whose answers may have changed since a model's training data.

### Why use it?

Use a search tool for time-sensitive or source-dependent questions, such as current office holders, recent events, or up-to-date product information. Without search, a model may answer from older knowledge or be unsure.

### Define and attach a search tool

```python
from typing import Any
from tavily import TavilyClient
from langchain.tools import tool

tavily_client = TavilyClient()

@tool
def web_search(query: str) -> dict[str, Any]:
    """Search the web for information."""
    return tavily_client.search(query)

agent = create_agent(
    model="gpt-5-nano",
    tools=[web_search],
)

response = agent.invoke({
    "messages": [
        HumanMessage(content="Who is the current mayor of San Francisco?")
    ]
})
print(response["messages"][-1].content)
```

The notebook calls `web_search.invoke(...)` directly in one cell to test the tool independently. The agent version lets the model decide to call it during a conversation. Tavily requires its package and API credentials.

For trustworthy answers, inspect sources returned by search and communicate uncertainty. Search results can be incomplete or wrong.

## 9. Memory and conversation threads

### Subject

Memory lets an agent retain conversation state across separate invocations. The notebook contrasts calls without a checkpointer with calls using an in-memory checkpointer.

### Why use it?

Without carried-over state, a separate invocation may not know facts from a previous call. Memory is useful for follow-up questions and ongoing conversations.

### No memory

```python
agent = create_agent("gpt-5-nano")

agent.invoke({
    "messages": [
        HumanMessage(content="My favourite colour is green.")
    ]
})

response = agent.invoke({
    "messages": [
        HumanMessage(content="What's my favourite colour?")
    ]
})
```

These are separate calls with no shared checkpoint in this setup, so the second call should not be expected to know the first fact.

### In-memory checkpointing

```python
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(
    "gpt-5-nano",
    checkpointer=InMemorySaver(),
)

config = {"configurable": {"thread_id": "user-1"}}

agent.invoke(
    {"messages": [HumanMessage(content="My favourite colour is green.")]},
    config,
)

response = agent.invoke(
    {"messages": [HumanMessage(content="What's my favourite colour?")]},
    config,
)
print(response["messages"][-1].content)
```

- `InMemorySaver()` stores checkpoint state in process memory.
- `thread_id` identifies which conversation's state to continue.
- Reuse the same `thread_id` for follow-up messages in that thread.
- Use a different ID for a separate conversation.

In-memory state is temporary: it is not a durable database and normally disappears when the process/kernel is restarted. Persistent applications need an appropriate durable checkpointer and careful privacy/retention rules.

## 10. Multimodal messages: text, images, and audio

### Subject

Multimodal means a model can work with more than one modality (type) of input or output. A message may combine text with an image, or text with audio.

### Why use it?

Use multimodal input when the task depends on information that is not just text—for example, describing a photo or interpreting a short audio recording.

### Text message

```python
question = HumanMessage(content=[
    {"type": "text", "text": "What is the capital of the Moon?"}
])
```

The content is a list of typed parts. In the image example, one part is text and another part contains the image data.

### Upload and encode an image

The notebook uses a Jupyter `FileUpload` widget:

```python
from ipywidgets import FileUpload
from IPython.display import display

uploader = FileUpload(accept=".jpg", multiple=False)
display(uploader)
```

After uploading a file:

```python
import base64

if not uploader.value:
    raise ValueError("Upload an image first.")

uploaded_file = uploader.value[0]
img_bytes = bytes(uploaded_file["content"])
img_b64 = base64.b64encode(img_bytes).decode("utf-8")
```

- `uploader.value[0]` selects the first uploaded file.
- `content` is the file's binary data (in this notebook, a `memoryview`).
- `bytes(...)` makes ordinary Python bytes.
- Base64 encodes binary bytes into text so the image can be represented in a text-based message format.
- Base64 is an encoding, **not encryption**; it does not make the image secret.

Avoid printing the full Base64 string in normal use: it can be enormous. Keep the original file private if it contains sensitive information.

### Send text and image together

```python
from langchain.messages import HumanMessage

question = HumanMessage(content=[
    {"type": "text", "text": "Describe this picture."},
    {
        "type": "image",
        "base64": img_b64,
        "mime_type": "image/jpeg",
    },
])

response = agent.invoke({"messages": [question]})
print(response["messages"][-1].content)
```

The MIME type must match the uploaded file. The notebook's uploader accepts `.jpg`, so `image/jpeg` is appropriate for JPEG files; use `image/png` for PNG files. A mismatch can prevent the model from interpreting the image correctly.

The text asks the question; the image provides the visual evidence. The system prompt should fit the task (for example, accurate image description rather than fictional-city generation).

### Record and send audio

The notebook demonstrates recording a short WAV clip, converting it to Base64, and including it in a message:

```python
import base64
import io
import sounddevice as sd
from scipy.io.wavfile import write

duration = 5
sample_rate = 44100
audio = sd.rec(
    int(duration * sample_rate),
    samplerate=sample_rate,
    channels=1,
)
sd.wait()

buffer = io.BytesIO()
write(buffer, sample_rate, audio)
wav_bytes = buffer.getvalue()
audio_b64 = base64.b64encode(wav_bytes).decode("utf-8")
```

Then send it with a text instruction, using a model/integration that supports the audio input format:

```python
audio_question = HumanMessage(content=[
    {"type": "text", "text": "Tell me about this audio."},
    {"type": "audio", "base64": audio_b64, "mime_type": "audio/wav"},
])
```

Recording requires a working microphone and audio packages such as `sounddevice` and `scipy`. Model and provider support for audio input varies; the model used for an image example may not support audio.

## 11. Putting it together: personal chef agent

### Subject

The personal-chef notebook combines a system prompt, a web-search tool, an agent, and a checkpointer.

### Why use it?

This demonstrates a realistic agent pattern: accept user-provided ingredients, search for recipe ideas, then answer in the role of a personal chef. Memory can preserve context for a follow-up such as asking for instructions for one suggested recipe.

### Core pattern

```python
from typing import Any
from tavily import TavilyClient
from langchain.tools import tool
from langchain.agents import create_agent
from langchain.messages import HumanMessage
from langgraph.checkpoint.memory import InMemorySaver

tavily_client = TavilyClient()

@tool
def web_search(query: str) -> dict[str, Any]:
    """Search the web for recipe information."""
    return tavily_client.search(query)

system_prompt = """
You are a personal chef. The user will list leftover ingredients.
Use web search to find recipes that can use those ingredients.
Suggest recipes, and provide instructions when asked.
"""

agent = create_agent(
    model="gpt-5-nano",
    tools=[web_search],
    system_prompt=system_prompt,
    checkpointer=InMemorySaver(),
)

config = {"configurable": {"thread_id": "chef-session-1"}}
response = agent.invoke(
    {"messages": [
        HumanMessage(content="I have leftover chicken and rice. What can I make?")
    ]},
    config,
)
print(response["messages"][-1].content)
```

To ask a follow-up, invoke the agent again with another `HumanMessage` and the **same** `config`. The thread ID connects it to the earlier conversation.

Recipe results from the web are suggestions, not a substitute for checking food-safety guidance, allergies, or ingredient labels.

## 12. Streaming output

### Subject

Streaming displays generated output incrementally instead of waiting for the entire answer.

### Why use it?

Streaming can make an interactive application feel more responsive, especially when answers take time to generate.

### Syntax from the notebook

```python
for token, metadata in agent.stream(
    {"messages": [
        HumanMessage(content="Tell me about a fictional Moon city.")
    ]},
    stream_mode="messages",
):
    if token.content:
        print(token.content, end="", flush=True)
```

Each iteration yields a message chunk and metadata. The `if token.content` guard skips empty chunks. `end=""` avoids adding a newline after every chunk; `flush=True` writes output promptly. Streaming behavior and chunk content can vary by model and integration.

## 13. Quick revision table

| Concept | What it is | Use it when |
|---|---|---|
| Model | Component that generates a response from input | A direct generation or question-answering call is enough |
| Prompt | Instructions and context | You need to guide the task, tone, or response style |
| Agent | Model-centered workflow that can use tools | The task may require actions or tool selection |
| Message | Content with a speaker/role, such as user or assistant | You need to represent a conversation |
| Tool | A callable operation made available to an agent | You need calculation, search, or an application action |
| Structured output | Response constrained by a schema | Code needs named, typed fields |
| Memory/checkpointer | Stored conversation state | The agent needs context across calls |
| Multimodal input | Message with text, image, audio, or other supported media | The task depends on more than text |
| Streaming | Incremental response delivery | You want to show output as it is generated |

## 14. Common mistakes to avoid

- Printing the whole response object when you only need the answer: use `response["messages"][-1].content` for an agent or `response.content` for a direct model call.
- Assuming a new invocation remembers old facts: configure memory and reuse the same `thread_id`.
- Giving an agent a role that conflicts with the user's task: align the system prompt with the desired behavior.
- Treating examples in a prompt as factual evidence: examples teach a pattern, not truth.
- Expecting an agent to use a tool just because it is available: explain when the tool should be used and inspect the returned messages.
- Mixing up a file's MIME type: JPEG generally uses `image/jpeg`; PNG uses `image/png`.
- Printing large binary or Base64 data: print file metadata or display the image instead.
- Treating Base64 as encryption: it is reversible encoding, not secrecy.
- Assuming a notebook's in-memory checkpointer survives a kernel restart: it does not provide durable storage.
- Sharing API keys, private images, or sensitive conversation data in notebook outputs or source control.

## 15. A simple decision guide

1. **Just need a model answer?** Initialize a model and call `invoke`.
2. **Need a role, policy, or style?** Add a system prompt.
3. **Need a repeatable field structure?** Define a Pydantic schema and request structured output.
4. **Need computation or fresh information?** Define and attach a tool.
5. **Need follow-ups to remember earlier turns?** Add a checkpointer and reuse the thread ID.
6. **Need image or audio understanding?** Send a correctly typed multimodal message to a model that supports that media.
7. **Need an interactive response?** Stream message chunks.
